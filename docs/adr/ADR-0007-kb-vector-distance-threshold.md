# ADR-0007: KB 벡터 검색 거리 임계값 조정

## Meta

- **Date**: 2025-12-02
- **Status**: Accepted
- **Authors**: 운영자, Claude
- **Related Session**: Phase 1-3 KB/RAG 개선 작업

## Context (배경)

- KB 서비스의 `/ask_llm` 엔드포인트가 "no relevant posts" 응답만 반환
- `KB_DIST_MAX=0.42`로 설정되어 있었으나, Google text-embedding-004 모델의 실제 거리 분포(1.0~1.1)와 맞지 않음
- 모든 유의미한 검색 결과가 임계값보다 높아 필터링되어 RAG 파이프라인 전체가 무력화

### 제약 조건
- 임베딩 모델 변경 불가 (이미 800+ 게시글 임베딩 완료)
- 기존 데이터 재생성 비용 고려

## Options Considered (고려한 대안)

### Option A: 임계값 그대로 유지, 임베딩 모델 변경
- 설명: 다른 임베딩 모델(OpenAI, Cohere 등)로 교체하여 거리 분포 조정
- 장점: 더 정밀한 거리 분포 가능
- 단점: 기존 801개 게시글 + 11개 매뉴얼 재임베딩 필요, API 비용 발생

### Option B: 임계값 완전 제거
- 설명: 거리 필터링 없이 top_k 결과만 사용
- 장점: 구현 간단
- 단점: 관련 없는 결과도 LLM에 전달되어 답변 품질 저하 가능

### Option C: 임계값을 1.5로 상향 (선택됨)
- 설명: `KB_DIST_MAX` 기본값을 0.42 → 1.5로 변경
- 장점:
  - 기존 임베딩 데이터 재사용
  - text-embedding-004의 실제 거리 분포에 적합
  - 환경변수로 추후 조정 가능
- 단점: 일부 노이즈 결과가 포함될 수 있음 (top_k로 제한되므로 영향 적음)

## Decision (결정)

**우리는 Option C (임계값 1.5로 상향)를 선택했다.**

그 이유는:
1. 기존 800+ 임베딩 데이터를 재생성 없이 활용 가능
2. Google text-embedding-004의 L2 거리 분포(0.5~1.3)에서 유의미한 결과 대부분 포함
3. 환경변수 `KB_DIST_MAX`로 운영 중 미세 조정 가능

### Invariants (불변식)
- `KB_DIST_MAX` 기본값은 1.5 유지
- 임베딩 모델 변경 시 임계값 재검토 필수
- 검색 결과에 `dist` 값 포함하여 모니터링 가능하게 유지

## Consequences (결과)

### 긍정적 효과
- RAG 파이프라인 정상화: `/ask_llm`에서 관련 게시글 기반 답변 생성
- 검색 결과에 dist 포함으로 품질 모니터링 가능
- 즉시 적용 가능 (재임베딩 불필요)

### 부정적 효과 / 리스크
- 임계값이 높아 일부 관련성 낮은 결과 포함 가능
- 향후 임베딩 모델 변경 시 임계값 재조정 필요

### 후속 작업
- [x] 코드 변경: `kb/service.py` - 기본값 0.42 → 1.5
- [x] 검증: `/ask_llm` 정상 응답 확인
- [ ] 모니터링: dist 분포 추적하여 임계값 최적화 검토

## AI Context (AI 협업 메모)

- Phase 1 작업 중 RAG 파이프라인 진단에서 발견
- Google text-embedding-004 모델의 L2 거리 특성:
  - 유사 문서: 0.5~0.9
  - 관련 문서: 0.9~1.2
  - 무관 문서: 1.3+
- 실제 검색 결과 dist 값이 0.6~1.1 범위에 분포
