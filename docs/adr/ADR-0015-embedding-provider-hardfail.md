# ADR-0015 — 임베딩 프로바이더 하드페일 및 OpenAI 전환

- 상태: Accepted
- 날짜: 2025-12-05

## Context
- Google `text-embedding-004` 사용 중 프로바이더 로드/호출 실패 시 `embed_texts`가 0벡터를 “폴백”으로 저장하도록 되어 있었음.
- 0벡터가 1,200여 건 쌓이며 벡터 검색 결과가 무작위/엉뚱한 게시글로 치우침. “사알못 다시보기 링크” 등 핵심 질의에 무관한 링크가 붙는 치명적 품질 저하가 발생.
- AGENTS.md에 “폴백 금지”가 명시되어 있으나 코드가 이를 위반.
- Google 임베딩은 짧은 한글 문장에서 유사도가 과도하게 높게 나오는 품질 리스크도 관찰됨.

## Decision
1. 임베딩 프로바이더 실패 시 **즉시 예외**를 던진다. 어떤 경우에도 0벡터/침묵 폴백을 허용하지 않는다.
2. 기본 임베딩 프로바이더를 **OpenAI `text-embedding-3-large`**로 전환한다.
3. 모든 기존 임베딩을 삭제 후 OpenAI 모델로 재생성한다(수행 완료).
4. 검색 로직은 dist 로그를 남기고, 빈 임베딩 발견 시 결과 0건으로 반환하여 조기 탐지한다.

## Consequences
- 품질: 0벡터로 인한 잘못된 상위 결과 위험 제거. OpenAI 모델로 한글 질의 매칭 안정성 향상.
- 비용/성능: OpenAI 호출 비용과 3072차원 벡터 저장 공간 증가. 재임베딩 시 10~15분 소요.
- 운영: 프로바이더 키 부재/오류가 즉시 드러나므로 장애 초기에 발견 가능.

## Follow-up
- CI/헬스체크에 “샘플 질의 → 벡터 norm 확인 → 결과 상위 dist 로그” 추가.
- dist 임계값 재튜닝 필요 시 별도 실험(현재 기본 0.42 그대로).
- 모델 교체가 필요해지면 본 ADR를 supersede하는 새 ADR 작성.
