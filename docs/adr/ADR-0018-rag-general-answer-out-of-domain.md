# ADR-0018: RAG 범위 밖 질의에 대한 일반 상식 답변 경로

## Meta

- **Date**: 2025-12-06
- **Status**: Accepted
- **Authors**: 운영자, PM AI, Claude Code
- **Related**: ADR-0005, ADR-0007, ADR-0014, ADR-0020

---

## Context

- 디하클 카페 RAG 시스템은 기본적으로 **카페 자료만을 근거로 답변**해야 하며, 임의의 폴백(fallback)을 금지한다.
- 그러나 실제 사용자는 다음과 같은 **카페 도메인 밖 일반 상식 질문**을 자주 던진다.
  - 예: “피자 만드는 법 알려줘”, “피타고라스 정리 증명해줘”
- 기존 동작에서는:
  - 벡터 검색 상 “애매하게 비슷한” 카페 글을 끌어와 템플릿에 억지로 끼워 넣거나,
  - “정보 없음” 텍스트에 의미 없는 링크/CTA가 붙는 문제가 반복되었다.
- PM 요청:
  - “카페 자료가 없더라도, **일반 상식 수준에서 성의 있게 답하도록 허용**하되,
  - 카페 자료와 혼동되면 안 되고, **첫 문장에 명시적으로 일반 상식 답변임을 밝혀야** 한다.”

---

## Decision

### 1) 질의 도메인 판별

- `kb/service.py`에 다음 보조 함수를 둔다.
  - `_is_domain_query(query: str) -> bool`  
    - 디하클/강의/사알못/강좌/무료특강/정규강의/다시보기/녹화/사주/일반반/비지니스반/포인트 등 **카페·강의 관련 키워드**가 하나라도 포함되면 `True`.
  - `_has_query_keyword_overlap`, `_has_manual_keyword_overlap`  
    - 질문 텍스트와 게시글/매뉴얼(제목+본문/요약) 사이에 의미 있는 부분 문자열 겹침이 있는지 검사.

- **플랫폼 사용법(일반 상식) 예외**  
  - 오픈채팅/네이버 카페/카카오톡 등 “플랫폼 사용법” 성격(알림/설정/검색/복사/URL 등)으로 판단되면,  
    일부 도메인 키워드가 포함되어 있더라도 `general_out_of_scope` 경로로 처리한다.  
  - 단, 강의/등업/포인트/사알못/사주랩 등 **강한 도메인 힌트**가 함께 있으면 예외로 도메인(RAG)로 유지한다.

- `AskLlmRequest`에는 선택 필드 `context_tags: Optional[list[str]]`를 둔다.
  - node-iris 쪽 `askKb.ts`에서 방 이름/질문 내용 기반으로 태그를 구성한다.  
    예: `["dinohighclass", "디하클", "사알못 강의", "sajulab"]` 등.
  - `/ask_llm`에서 `context_tags`는 기본적으로 “검색 힌트”로만 사용한다.
  - 다만 Sajulab 강제 태그(`sajulab`, `sajulab.kr`, `사주랩`)가 포함되면 **도메인 질의로 강제**한다.

### 2) 일반 상식 답변 경로 (`_build_general_answer`)

- 도메인 판별 결과, **카페와 무관한 일반 상식 질의**라고 판단되면:
  - `/ask_llm`에서 벡터 검색/RAG 파이프라인을 건너뛰고, `_build_general_answer`를 호출한다.
  - `_build_general_answer`는 OpenAI LLM에 다음 지침으로 프롬프트를 전달한다.
    - 첫 문장은 항상 정확히 다음 문장으로 시작해야 한다.  
      > `가이드라인에는 없지만, 일반 상식으로 답변드립니다.`
    - 디하클 카페 내부 자료나 강의/다시보기 링크가 있는 것처럼 **절대 꾸미지 않는다.**
    - 어떤 외부 사이트 URL도 넣지 않는다(https:// 포함 금지).
    - 3~6문장 정도의 간결한 한국어 설명만 제공한다.
    - 모르는 부분은 “모릅니다/추측입니다”를 명시한다.
  - 응답 JSON:
    - `manuals: []`, `posts: []`
    - `link_hint: ""`
    - `diag.mode: "general_out_of_scope"` 등으로 경로 표시

### 3) RAG 경로와의 구분

- 아래 조건 중 하나라도 만족하면 **반드시 RAG 템플릿 경로**를 사용한다.
  - `_is_domain_query(query)` 가 `True`인 경우
  - Sajulab 강제 태그가 포함된 경우
- 반대로, 아래 조건을 모두 만족할 때만 일반 상식 경로로 보낸다.
  - `_is_domain_query(query)` 가 `False` 이고
  - Sajulab 강제 태그가 없는 경우

---

## Invariants

1. **카페 도메인 질문**에 대해서는 여전히:
   - RAG 검색 + 필터 + 재랭크 + 템플릿 기반 답변만 사용한다.
   - “정보 없음”일 때 임의의 링크/CTA를 절대 생성하지 않는다.
2. **도메인 밖 일반 상식 질문**에 대해서만:
   - `_build_general_answer` 경로를 사용하며,  
     첫 문장 프리픽스와 “링크 없음” 제약을 항상 지킨다.
3. 일반 상식 경로가 발동했을 때는:
   - `diag.mode`에 `general_*` 값을 남겨 운영/디버깅 시 경로를 명확히 구분할 수 있어야 한다.

---

## Consequences

### Positive

- 사용자는 “피자 만드는 법 알려줘” 같은 질문에 대해:
  - 더 이상 의미 없는 “정보 없음 + 엉뚱 링크”를 받지 않고,
  - “가이드라인에는 없지만, 일반 상식으로 답변드립니다.”로 시작하는 직관적인 답변을 받게 된다.
- 카페 도메인 질문(강의/다시보기/날짜 질의 등)에 대해서는:
  - 기존 RAG 품질/제약을 그대로 유지하므로, SSOT/폴백 금지 원칙이 깨지지 않는다.

### Negative / Risks

- 일반 상식 답변의 품질/톤이 RAG 답변과 다를 수 있다.
- 도메인 판별 규칙이 잘못되면:
  - 카페와 실제로 관련 있는 질문이 일반 상식 경로로 빠질 수 있다.
  - 반대로, 일반 상식 질문이 RAG 경로로 잘못 들어갈 수 있다.
- 이를 완화하기 위해:
  - 도메인 키워드 목록은 ADR/코드에 명시하고, 변경 시 반드시 PR/리뷰를 거치도록 한다.
  - `scripts/verify_rag.py`에 일반 질문 케이스를 포함해 회귀를 막는다.
