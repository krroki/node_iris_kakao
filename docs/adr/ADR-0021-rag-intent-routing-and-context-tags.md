# ADR-0021: RAG 질의 라우팅 / 컨텍스트 태그 / 일반 상식 경로 정렬

## Meta

- **Date**: 2025-12-09
- **Status**: Accepted
- **Authors**: PM AI, Claude Code
- **Related**: ADR-0010, ADR-0011, ADR-0014, ADR-0018, ADR-0020

## Context

최근 다음과 같은 문제가 반복되었다.

1. `?디하클 ...` 형식으로 들어온 **명백한 카페/강의 질문**이  
   `_is_domain_query` 키워드 판정에서 떨어져 `/ask_llm` 내부에서 `general_out_of_scope` 경로로 빠짐.
2. 질문에 “[MF:...]” 미러 마커, 인코딩 모지바이크 등이 섞여 있을 때
   - `CustomMessageController`에서 prefix/텍스트 추출이 불안정하게 동작하면서
   - RAG에 도달하기 전에 질문이 깨진 문자열로 전달되고,  
     그 결과 LLM이 템플릿은 유지하지만 **내용은 ‘정보 없음 + 엉뚱한 링크’**로 채우는 문제가 발생.
3. Sajulab 수강생용 사용법처럼 **특정 방(사알못 강의방)에서만 의미 있는 도메인 지식**이  
   `_is_domain_query` 키워드만으로는 포착되지 않아, general 경로로 빠지거나  
   전혀 다른 매뉴얼/게시글을 근거로 답변하는 경우가 있었다.

사용자 입장에서의 체감은 다음과 같다.

- “내가 만들어준 템플릿 구조는 유지되는데, 내용은 ‘정보 없음’이거나 전혀 상관없는 링크가 붙는다.”
- “어제까지 잘 되던 ‘강의 날짜/다시보기/가격/포인트’ 질문이 어느 날 갑자기 엉뚱한 답을 낸다.”
- “의도 파싱은 LLM이 하라고 했는데, 정작 규칙 레이어에서 잘못 걸러져서 LLM이 제대로 판단해 볼 기회도 못 얻는다.”

문제의 본질은 **도메인/비도메인 라우팅과 RAG vs 일반 상식 경로 선택이 규칙 기반 계층에 과도하게 묶여 있고,  
이 계층이 자주 삐끗한다는 것**이다.

---

## Decision

### 1) `?디하클` 계열 질문은 기본적으로 “도메인 RAG 질의”로 고정

- node-iris `CustomMessageController.aiQuery`는 `?디하클 ...` prefix를 갖는 메시지만 KB 질의 대상으로 삼는다.
- `node-iris-app/src/utils/askKb.ts`에서:
  - 모든 질의에 기본 컨텍스트 태그를 부여한다.
    - 예: `["dinohighclass", "디하클", "디지털 하이클래스 카페"]`
  - 사알못 강의방(방 이름에 `"사알못"` 포함)에서,
    - 질문에 `"사이트", "로그인", "포인트", "분석", "결과", "PDF", "sajulab", "사주랩"` 등이 포함되면
    - 추가 태그: `["sajulab", "sajulab.kr", "사알못 강의 수강생", "Sajulab 수강생용 사용법"]` 을 부여한다.
- `kb/service.py::AskLlmRequest`:
  - `context_tags: Optional[list[str]]` 필드 도입.
  - `/ask_llm`에서 `context_tags`가 있으면 기본적으로 “도메인(RAG) 질의”로 판단한다.
    - 배경: node-iris는 `?디하클` 접두어를 제거한 “질문 본문”만 전달하므로, 태그가 없으면 `_is_domain_query`만으로는 도메인 의도를 놓칠 수 있다.
  - `context_tags`는 동시에 “검색 힌트”로도 사용한다(태그 문자열을 벡터 검색 쿼리 앞에 붙여 히트율을 올림).
  - 다만 Sajulab 수강생용처럼 강하게 컨텍스트가 고정된 태그(`sajulab`, `sajulab.kr`, `사주랩`)가 포함되면 **도메인=True를 강제**한다(일반상식 예외 분기 금지).

### 2) `/ask_llm`에서 RAG vs 일반 상식 경로를 명확히 분리

- 도메인 질의 판단:
  - `context_tags`가 있으면 → **도메인 질의(기본)**.
  - `context_tags`가 없으면 `_is_domain_query(query)=True`일 때만 도메인 질의로 본다.
  - 단, Sajulab 강제 태그가 있으면 항상 도메인 질의로 강제한다.
- 일반 상식 경로로 가는 조건:
  - Sajulab 강제 태그가 없고,
  - `_is_general_knowledge_query(query)=True` 또는 `_is_platform_usage_query(query)=True` 인 경우
  - → `general_out_of_scope`로 처리(고정 프리픽스 + URL 출력 금지).
- 그 외의 경우:
  - `_build_prompt` 기반 **디하클 RAG 템플릿** 경로를 사용한다.

### 3) link_hint · 폴백 링크 정책 정리

- `kb/service.py`:
  - `link_hint`는 **검색된 게시글의 URL을 그대로 노출하는 힌트**로만 사용한다.
  - `posts`가 있고, 선택된 게시글의 URL이 신뢰할 수 있을 때만 `link_hint`를 채운다.
- `node-iris-app/src/utils/askKb.ts`:
  - LLM 답변에 이미 URL/링크 안내가 있으면 `link_hint`를 추가하지 않는다.
  - 답변 내용이 `"정보 없음" / "찾지 못했" / "관련 정보 없음" / "자료 부족" / "다시 시도"` 류 패턴이면  
    링크를 억지로 붙이지 않는다.
- 결과적으로:
  - “정보 없음 + 엉뚱한 링크” 패턴은 허용하지 않는다.
  - 링크는 항상 **벡터 검색/RAG로 실제 선택된 게시글에 근거**해야 한다.

### 4) Sajulab 수강생 질문용 컨텍스트 태그

- 특정 방(사알못 강의 전용 오픈채팅방)에서:
  - 로그인/포인트/분석/PDF 관련 질문이 들어오면,
  - 컨텍스트 태그에 `"sajulab"` 계열 태그를 추가한다.
- `/ask_llm`에서:
  - `context_tags`를 벡터 검색 쿼리 앞에 붙여서
    - `[KB] Sajulab 수강생용 사용법` 매뉴얼,  
      `[KB] 사알못 강의 가격·포인트 정책` 등 관련 매뉴얼을 우선적으로 히트시키게 한다.
  - `_is_domain_query` 결과와 무관하게 **도메인=True** 로 취급하므로  
    Sajulab 질문이 general 경로로 빠지지 않게 한다.

## Invariants

1. **도메인 질의 (카페/강의/사알못/가격/포인트/다시보기 등)**  
   - `/ask_llm`에서는 `context_tags`가 있으면 기본적으로 도메인으로 판단한다.
   - `context_tags`가 없을 때만 `_is_domain_query(query)=True` 여부로 도메인을 판단한다.
   - 도메인 질의는 항상 RAG 템플릿 경로를 사용해야 한다.

2. **일반 상식 질의**  
   - Sajulab 강제 태그가 없고 `_is_general_knowledge_query` 또는 `_is_platform_usage_query`가 참이면 `_build_general_answer`를 사용한다.
   - 이 경로는 항상 고정 프리픽스로 시작하고, URL을 출력하지 않는다.

3. **링크/CTA 출력**  
   - 링크/CTA는 항상 실제 카페 게시글/매뉴얼의 URL을 근거로 해야 한다.
   - 일반 상식 경로에서는 링크를 절대 출력하지 않는다.
   - RAG 경로에서도 URL이 없는 경우 해당 줄 자체를 생략하고, 임의로 URL을 구성하지 않는다.

4. **diag.mode 값**  
   - 일반 상식 경로: `general_*` 접두어를 사용한다 (`general`, `general_out_of_scope` 등).
   - RAG 경로: `general_*` 가 아닌 값만 사용한다.
   - 로그/테스트/대시보드에서 두 경로를 명확히 구분할 수 있어야 한다.

5. **가격·포인트 질문의 숫자 응답**  
   - 질문에 `가격/수강료/비용/얼마/금액/포인트` 계열 키워드가 있고,  
     관련 매뉴얼(예: `[KB] 사알못 강의 가격·포인트 정책`) 본문에 숫자 정보가 존재한다면:
     - 답변에는 해당 숫자(예: `177만`, `255만`, `50만`, `100만`, `30만`)가 반드시 포함되어야 한다.
     - 이런 숫자가 하나라도 있는 상태에서는 `정보 없음` 또는 `자료 기준으로 확인 불가`를  
       가격·포인트 전체에 대한 결론으로 사용하지 않는다.
   - 숫자가 전혀 없는 경우에만 “자료 기준으로 확인 불가”라고 명시한다.

---

## Consequences

### Positive

- `?디하클 ...` 계열 카페/강의 질문은  
  더 이상 일반 상식 경로로 빠지지 않고, 항상 RAG 템플릿+카페 자료 기반으로 처리된다.
- “사알못 비지니스반 가격/포인트”처럼 명확한 도메인 질문에 대해  
  `[KB] 사알못 강의 가격·포인트 정책` 매뉴얼이 안정적으로 사용된다.
- Sajulab 수강생용 질문은 방 이름/키워드 기반 컨텍스트 태그 덕분에  
  일반 상식 경로가 아니라 Sajulab 매뉴얼을 근거로 답변하게 된다.
- “정보 없음 + 엉뚱한 링크” 패턴이 차단되어, 신뢰도와 일관성이 높아진다.

### Negative / Risks

- `context_tags` 설계가 잘못되면:
  - 너무 많은 질문이 “도메인=True”로 간주되어 일반 상식 경로가 거의 사용되지 않을 수 있다.
  - 반대로 필요한 태그가 누락되면 여전히 `_is_domain_query` 키워드 목록에 의존하게 된다.
- node-iris와 KB 서비스 사이의 계약에 `context_tags`가 추가되므로,
  - 양쪽 버전 불일치 시 일시적으로 태그가 무시될 수 있다 (기본값 처리 필요).
