# ADR-0022: Welcome 템플릿 세트 + 카카오 기본 닉네임 분기

- **Status**: Accepted
- **Authors**: PM AI, Codex CLI
- **Related**: ADR-0016(SAFE_MODE), ADR-0011(Bot Singleton), docs/runbook/quickstart_vm_iris_adb.md, agents.md

## Context

현재 welcome 기능은 `runtime.json.templateByFeature.welcome`(또는 레거시 `welcomeTemplateName`)에 **단일 템플릿 이름**을 지정하고,
신규 입장 이벤트(`CustomNewMemberController`)에서 해당 템플릿을 로드해 환영 문구/이미지를 발송한다.

운영 요구는 다음 두 가지였다.

1. 환영인사 문구를 여러 개 준비해두고, 신규 입장마다 **“템플릿 세트”에서 1개를 선택**해 발송(반복/피로도 완화).
2. 신규 입장자의 닉네임이 **카카오 “기본 닉네임(익명/카카오프렌즈 기본닉)”** 인지 여부에 따라,
   서로 다른 템플릿 세트를 적용(기본닉이면 “닉 변경 유도” 세트, 아니면 “일반 환영” 세트).

또한 “카카오 기본 닉네임” 정의/판별 로직은 **웹 근거**를 남기고, 운영자가 바꿀 수 있어야 한다.

---

## Web Evidence (근거)

### 1) (공식) 오픈채팅/오픈프로필은 “닉네임을 편집/관리”할 수 있는 별도 프로필이다

카카오 고객센터(공식) 문서에서 오픈채팅의 **오픈프로필**은 “프로필 이미지/닉네임 등을 편집”할 수 있다고 안내한다.
즉, 오픈채팅에서는 참여자가 “프로필/닉네임을 설정하는 상태”가 명확히 존재한다.

- https://cs.kakao.com/helps_html/1073209485

또한 방장이 “기본프로필로만 참여 허용”을 켠 경우, **카카오톡 기본 프로필 외 다른 프로필로 변경이 불가**하다고 명시한다.
이는 “기본 프로필”과 “오픈프로필(또는 다른 프로필)”이 정책/설정 수준에서 구분됨을 보여준다.

- https://cs.kakao.com/helps_html/1073209474

### 2) (운영 관측 + UI 근거) 오픈채팅에는 “임시/커스텀 프로필(카카오프렌즈)” 상태가 존재한다

오픈채팅 프로필 변경 안내(사용자 가이드)에서, 오픈채팅 참여 프로필이
“현재 오픈프로필” vs “현재 임시/커스텀 프로필(카카오프렌즈)”로 구분되어 설명된다.

- https://1oak.tistory.com/22

따라서 본 프로젝트에서 말하는 “카카오 기본 닉네임”은 다음 의미로 SSOT 정의한다.

- **오픈채팅 입장 시 ‘임시/커스텀 프로필(카카오프렌즈)’ 상태로 참여하는 사용자에게 자동 부여되는(또는 자주 관측되는) 기본 닉네임 패턴**

> NOTE: 카카오 로그인 API의 `is_default_nickname` 플래그는 “카카오 계정 프로필” 기준이며,
>       오픈채팅의 “임시/커스텀 프로필(카카오프렌즈)”과 1:1로 동일하다고 가정하지 않는다.
>       본 프로젝트는 IRIS 이벤트에서 제공되는 `userName` 문자열만으로 분기하므로,
>       오픈채팅 기본닉은 **운영 관측 기반(정규식 리스트)** 으로만 판별한다.

### 3) (공식 IP) 니니즈/춘식이/프렌즈 캐릭터군은 공식적으로 확장되어 있다

과거(라이언/어피치/무지/콘/튜브/프로도/네오/제이지) 중심의 “8명 캐릭터”만으로는
최근 오픈채팅 기본닉(예: **니니즈/춘식이/죠르디/앙몬드/스카피/팬더주니어/케로&베로니/콥&빠냐**)를 커버할 수 없다.

공식 IP 소개(카카오프렌즈 비즈니스 사이트)에서 다음이 확인된다.

- 카카오프렌즈 캐릭터군 및 ‘Choonsik(춘식)’ 포함: https://kakaofriends-business.com/kakaoFriends
- Choonsik 상세: https://kakaofriends-business.com/kakaoFriends/choonsik
- NINIZ(니니즈) 및 Jordy/Angmond/Scappy/Penda Jr/Cob&Bbanya/Kero&Berony 포함: https://kakaofriends-business.com/niniz

### 4) (제약) IRIS 이벤트만으로는 “기본닉 플래그”를 받을 수 없음

본 프로젝트는 카카오 OAuth/프로필 API를 호출하지 않고, **IRIS 이벤트에서 제공되는 `userName` 문자열**만으로
welcome 분기(기본닉 vs 커스텀닉)를 수행한다.
따라서 오픈채팅 UI/정책의 “임시/커스텀 프로필 여부” 같은 플래그를 직접 받을 수 없으며,
운영 관측 기반 규칙(정규식 리스트)으로 판별한다.

### 5) (운영 관측) 오픈채팅 기본닉네임 생성 패턴

오픈채팅(오픈프로필) 기본 닉네임은 단일 고정 문자열이 아니라, 일반적으로 **(상태/동작/형용사) + (캐릭터/그룹명)** 조합으로 반복 생성된다.
따라서 “기본닉 판별”은 단일 정규식 1개로 끝내기보다,
운영에서 관측되는 패턴을 정규식 리스트로 확장 가능하게 두는 것이 안전하다.

### 4) 운영 관측 예시(최근, 2025-12-13)

운영자가 오픈채팅에서 직접 관측한 “기본닉” 예시(발췌):

- 웃고있는 니니즈 / 울고있는 니니즈 / 나른한 니니즈 / 응원하는 니니즈
- 간식 먹는 프렌즈 / 쉬고있는 프렌즈 / 인사하는 프렌즈 / 멍한 프렌즈
- 인사하는 춘식이 / 박스에 들어간 춘식이 / 행복한 춘식이
- 집 지키는 죠르디 / 일하는 죠르디 / 누워있는 죠르디
- 생각이 많은 스카피 / 손 흔드는 스카피
- 평온한 앙몬드 / 부끄러운 앙몬드
- 여행 가는 팬더주니어 / 손 흔드는 팬더주니어

따라서 “기본닉” 판별은 고정된 구(8명 캐릭터)로 제한하지 않고,
운영 관측에 맞춰 정규식/베이스 네임을 계속 업데이트할 수 있어야 한다.

## Decision

### 1) Welcome “템플릿 세트” 개념 도입 (runtime.json 확장)

`node-iris-app/config/runtime.json`에 아래 설정을 **추가(옵션)** 한다.

```json
{
  "welcome": {
    "sendDelayMinMs": 3000,
    "sendDelayMaxMs": 5000,
    "templateSets": {
      "kakaoDefaultNickname": ["1", "2", "welcome_default_3", "welcome_default_4", "welcome_default_5"],
      "customNickname": ["welcome_custom_1", "welcome_custom_2", "welcome_custom_3", "welcome_custom_4", "welcome_custom_5"]
    },
    "templateSetPick": "random",
    "kakaoDefaultNicknameRegexes": [
      "^(?:라이언|어피치|무지|콘|튜브|프로도|네오|제이지|춘식이|프렌즈|니니즈|죠르디|앙몬드|스카피|팬더주니어|팬더 주니어|팬다|케로|베로니|케로&베로니|케로 & 베로니|콥|빠냐|콥&빠냐|콥 & 빠냐)$",
      "^[가-힣0-9]{1,12}하는\\s+(라이언|어피치|무지|콘|튜브|프로도|네오|제이지|춘식이|프렌즈|니니즈|죠르디|앙몬드|스카피|팬더주니어|팬더 주니어|팬다|케로|베로니|케로&베로니|케로 & 베로니|콥|빠냐|콥&빠냐|콥 & 빠냐)$",
      "^[가-힣0-9]{1,12}\\s+(라이언|어피치|무지|콘|튜브|프로도|네오|제이지|춘식이|프렌즈|니니즈|죠르디|앙몬드|스카피|팬더주니어|팬더 주니어|팬다|케로|베로니|케로&베로니|케로 & 베로니|콥|빠냐|콥&빠냐|콥 & 빠냐)$",
      "^[가-힣0-9]{1,12}(?:\\s+[가-힣0-9]{1,12}){1,3}\\s+(라이언|어피치|무지|콘|튜브|프로도|네오|제이지|춘식이|프렌즈|니니즈|죠르디|앙몬드|스카피|팬더주니어|팬더 주니어|팬다|케로|베로니|케로&베로니|케로 & 베로니|콥|빠냐|콥&빠냐|콥 & 빠냐)$"
    ]
  }
}
```

- `welcome.templateSets.kakaoDefaultNickname`: “기본닉”으로 입장한 사용자에게 적용할 템플릿 이름 리스트
- `welcome.templateSets.customNickname`: 기본닉이 아닌 사용자에게 적용할 템플릿 이름 리스트
- `welcome.templateSetPick`:
  - `random`(권장): 세트 내에서 **매 입장 이벤트마다 1개를 무작위로 선택**한다.
  - `hash_sender_id`: `senderId` 기반으로 템플릿을 결정(재현 가능, 상태 저장 불필요). `senderId`가 비어 있으면 `userName`으로 대체한다.
  - `hash_user_name`: `userName` 기반으로 템플릿을 결정
- `welcome.kakaoDefaultNicknameRegexes`: 기본닉 판별 정규식 목록(필수, 운영에서 변경 가능)
- `welcome.sendDelayMinMs` / `welcome.sendDelayMaxMs`:
  - 신규 입장 welcome 발송 지연(밀리초).
  - **최소값(sendDelayMinMs) 동안 입장자를 묶어서 처리**하고, 최종 발송은 `min~max` 사이로 랜덤 지연된다.
  - 운영 권장: 3000~5000ms (사람이 “관리자가 보고 있다”는 착각을 주는 지연)

### 2) “기본닉” 판별은 **정규식 기반(명시적)**

“카카오 기본 닉네임”은 서비스/언어/UI 업데이트에 따라 바뀔 수 있으므로,
코드에 애매한 휴리스틱을 고정하지 않고 **정규식 리스트**로만 판별한다.

- 기본 제공 정규식은 “(…하는) + (카카오프렌즈 캐릭터명)” 형태를 타겟한다.
- 또한 일부 기본닉은 캐릭터명 단독(예: `춘식이`, `팬더주니어`)으로 들어오는 케이스가 있어, 단독 캐릭터명 패턴도 포함한다.
- 운영 중 관측되는 기본닉 패턴이 추가되면,
  `runtime.json.welcome.kakaoDefaultNicknameRegexes`에 정규식을 추가하여 즉시 반영한다.

### 3) 세트 설정이 존재하면 “단일 템플릿”은 사용하지 않는다

`welcome.templateSets`가 설정된 경우:

- 신규 입장 welcome은 **반드시** `kakaoDefaultNickname` 또는 `customNickname` 세트에서만 선택한다.
- 세트/정규식/선택 방식이 불완전하거나 템플릿 파일이 없으면 **조용히 폴백하지 않고** 에러를 로그로 남긴 뒤 스킵한다.

세트 설정이 **없으면** 레거시 동작을 유지한다.

- `templateByFeature.welcome` → `welcomeTemplateName` → (옵션) `ALLOW_ENV_WELCOME_TEMPLATE=true`일 때만 env

## Invariants

1. **SAFE_MODE=true면 welcome 발신은 0건**이어야 한다. (ADR-0016)
2. 세트 기반 welcome에서 **폴백 금지**(임의 템플릿/문구 대체, 에러 무시하고 진행)는 금지한다.
   - `welcome.templateSets`가 켜져 있으면 `templateSetPick`, `kakaoDefaultNicknameRegexes`, 두 세트 배열은 모두 **필수**이며,
     누락/오류 시에는 에러를 남기고 스킵한다.
3. “기본닉” 판별은 **정규식(명시된 규칙)만** 사용한다.  
   - 정규식이 깨졌거나 세트가 불완전한 상태에서 임의로 “대충 맞추기”를 하지 않는다.
4. IRIS 기본 제공/레거시 환영 문구(예: 숫자 템플릿명 `"1"`, `"2"`, `welcome_default_*`)는 **자동 선택 경로에서 차단**한다.  
   - 운영 템플릿은 사람이 의미를 알 수 있는 이름(예: `welcome_custom_*`, `welcome_kakao_default_*`)으로만 관리한다.

## Consequences

### Positive

- welcome 문구 반복 피로도 감소(세트에서 분산).
- “기본닉” 사용자에게만 닉 변경 유도 템플릿을 적용해 불필요한 안내를 줄인다.
- 운영자가 정규식/세트만 조정하면 코드 변경 없이 정책 업데이트 가능.

### Negative / Risks

- 정규식/세트 구성이 잘못되면 welcome이 스킵될 수 있다. (의도된 안전장치)
- “기본닉” 패턴이 바뀌면 정규식 갱신이 필요하다.

## Implementation Notes

- 환영 문구 SSOT는 `welcome sample.txt`를 기준으로 한다(줄바꿈 포함).
- 공통 이미지(하트 인증 안내)는 `assets/welcome/common/KakaoTalk_20251213_123012048.png`(2013x1529)를 사용한다.
- 템플릿 변수 표기는 `{{entrance}}`(일반 치환) / `{entrance}`(레거시) / `@{entrance}`(멘션+치환) 를 모두 지원한다.
  - `@{entrance}`는 텍스트 치환과 함께 “멘션 송신”도 트리거한다(지원 환경에서만).
- 다중 입장(딜레이 윈도우 내 2명 이상 합류) 처리:
  - 변수: `{entrance1}`, `{entrance2}` … / `{{entrance1}}` … / `@{entrance1}` … 를 지원한다(없는 인덱스는 빈 문자열).
  - 템플릿이 여전히 `@{entrance}` 1개만 쓰고 있어도, 실제 발송 시에는 **동일 그룹의 입장자 전원을 멘션**하도록 자동 확장된다.
  - 세트 모드(`welcome.templateSets`)에서도 **배치 윈도우 내 입장자는 1개의 welcome 메시지로 통합 발신**한다.
    - 기본닉/커스텀닉이 섞였더라도 2번 나누어 보내지 않는다(운영 요구: “연달아 들어오면 동시에 처리”).
    - 템플릿 선택(기본닉 유도 vs 일반 환영)은 가능하면 **커스텀닉 입장자 기준으로 우선 선택**해,
      “기본닉 변경 유도” 문구가 커스텀닉 사용자에게 섞이지 않도록 한다.
- UI(`/settings`)에서 세트/정규식 편집 + 닉네임 판별 테스트 + 템플릿 미리보기(이미지 포함)를 제공한다.
