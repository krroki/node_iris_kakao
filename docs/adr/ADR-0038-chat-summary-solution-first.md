# ADR-0038: 채팅 요약(chatSummary) “해결책/결론” 중심(Q&A) 요약으로 전환

## Meta

- **Date**: 2025-12-17
- **Status**: Accepted
- **Authors**: 사용자, GPT-5.2
- **Related Session**: `docs/sessions/main.md`

## Context (배경)

`!요약`(chatSummary) 결과가 “무슨 대화가 오갔는지(Topic)”만 나열하고,
정작 사용자가 원하는 “그래서 결론이 뭐야 / 어떻게 해결해?”가 빠져 **정보 가치가 낮게** 느껴졌다.

대표적인 문제 패턴:

- “~에 대해 이야기가 나왔어요”, “조언이 오갔어요”, “논의했습니다” 같은 **메타 설명**이 많음
- 사용자가 **바로 적용할 수 있는 해결책/절차/단축키/메뉴 경로/기간**이 요약에서 누락됨
- 잡담/인사/리액션이 섞여 요약이 흐려짐

운영 목표는 “사람이 PDF로 정리한 요약처럼, 질문과 해결책이 바로 보이는 결과”다.

## Options Considered (고려한 대안)

### Option A: 현재 요약 유지(토픽 중심 요약)
- 장점: 구현 변경 최소
- 단점: “결론/해결책이 없다”는 불만이 지속

### Option B: LLM 프롬프트만 약하게 보강
- 장점: 빠른 개선
- 단점: 메타 문장/토픽 나열이 재발할 수 있음

### Option C: “해결책 중심(Q&A)” 요약 규칙을 명시 + 입력을 정보성 중심으로 발췌 (선택)
- 장점: 요약이 **문제→해결**로 구조화되어 실사용 가치가 높아짐
- 단점: 발췌 로직이 보수적이면 일부 맥락이 누락될 수 있음

## Decision (결정)

**우리는 Option C를 선택한다.**

`!요약`(chatSummary)은 토픽 나열이 아니라, 상위 3~5개 “문제/질문(Q) → 해결책/결론(A)” 형태로 요약한다.

### Invariants (불변식)

- “~에 대해 이야기했다/논의했다/공유됐다/조언이 오갔다/언급됐다” 같은 **메타 설명 문장 금지**
- 각 항목은 반드시 **Q(질문/이슈) → A(해결책/팁/결론)** 구조
- 로그에 구체 정보(단축키, 메뉴 위치, 기간/숫자, 링크)가 있으면 **반드시 포함**
- 잡담/인사/리액션은 제외하고, 정보성 대화(질문, 팁, 노하우, 해결책)만 선택
- 로그에 해결책이 없으면 **추측하지 않고**, “아직 구체적인 해결책은 안 나왔어요 😥”처럼 솔직하게 처리
- 발신 메시지 스타일/금지 규칙은 `ADR-0036` 및 `docs/reference/outbound-message-style.md`를 따른다
  - userId/타임스탬프/로그 원문 인용 금지
  - 링크는 푸터(구분선 `---` 아래)로만 출력, 링크가 없으면 푸터 자체 금지

## Consequences (결과)

### 긍정적 효과
- 요약이 “읽고 바로 적용 가능한 해결책” 중심으로 바뀌어 만족도 상승
- 토픽 나열/메타 설명이 줄어 정보 밀도가 높아짐

### 부정적 효과 / 리스크
- 정보성 발췌가 과도하면 일부 맥락이 빠질 수 있음(필요 시 `!요약 24시간` 등 기간 확장으로 보완)
