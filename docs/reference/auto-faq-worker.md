# 무명령어 자동 FAQ(질문 트리거) – 설계/가드레일

> 목표: `!` 같은 명령어 없이 **일반 채팅에서 ‘질문’을 감지**해, 운영자가 미리 등록한 답변을 **답장(Reply)** 으로 자동 발신한다.
>
> 전제: 오답/오인식(질문 아닌데 답변, 엉뚱한 답변) 방지를 최우선으로 하며, **애매하면 침묵**한다.

---

## 1) 왜 “후보 추출 → 승인 → 자동응답” 2단계인가

- “전체 로그에서 자동 학습 → 즉시 자동응답”은 오답 리스크가 너무 크다.
- 따라서 본 기능은 **1) 로그에서 질문 후보를 추출/랭킹**하고,
  운영자가 UI에서 **2) 승인/편집/스코프(글로벌/강의ID/방별) 지정**한 것만 자동응답한다.

---

## 2) 스코프(글로벌 vs 강의ID vs 방별)

- **글로벌**: 모든 방에서 공통으로 쓰는 Q/A (예: 앱 사용법/문의 채널)
- **강의ID**: 한 강의(= 여러 방 묶음: 사담/공지/프리미엄)에서 공통으로 쓰는 Q/A
- **방별**: 특정 방에서만 유효한 Q/A

우선순위(충돌 시):
1. 방별
2. 강의ID
3. 글로벌

---

## 3) 질문 트리거 파이프라인(정밀도 우선)

### 3.0 발신 메시지 스타일(필수)

- 자동 FAQ가 발신하는 답변(Reply 포함)은 **튜브렌즈 스타일**을 따른다:
  - `docs/reference/outbound-message-style.md`
- 특히 아래 금지 규칙은 자동 FAQ에서도 그대로 적용된다:
  - “찾아봤어요!” 같은 **서두 단독 시작 금지**(첫 줄은 결론)
  - 링크가 없으면 **푸터 자체 출력 금지**(“없음” 금지)
  - 로그/타임스탬프/캡처 메타 라인 금지

### 3.1 입력

- SSE(`/logs/stream`)의 `payloadType=message` 중 텍스트(`messageType=1`)만 대상
- 스태프/관리자/봇(iris 포함) 메시지는 기본 **무시**(루프/오인식 방지)

### 3.2 매칭(등록된 트리거만)

1) **스코프 필터**(방/강의ID/글로벌 + enabled)  
2) **부정 키워드/정규식(negativePattern)** 먼저 검사 → 걸리면 탈락  
3) **정확 일치(exact)** → **정규식(regex)** 순으로만 매칭 (fuzzy는 기본 OFF)  
4) 최종 매칭이 **1개**면 발신, **2개 이상이면 무응답**(ambiguous)

### 3.3 스팸/중복 방지

- 동일 사용자 + 동일 트리거: 쿨다운(예: 10분)
- 동일 메시지/유사 메시지: messageId 기반 dedupe
- 워커 진단/실패 알림은 **테스트용 오픈채팅방(18462226881291012)** 으로만 발신
  - 알림은 여러 건을 **1개 메시지로 배치**해 스팸을 방지한다.

## 4) “매주 바뀌는 링크/일정” (무료특강/다시보기/보너스) 대응 – 핵심 원칙

### 4.1 원칙: 링크/일정은 절대 하드코딩/추측하지 않는다

- “이번 무료강의 링크”, “결제 링크”, “다시보기 링크”, “보너스 프로그램 지급”은 주기적으로 바뀐다.
- 따라서 자동응답은 **KB(카페 글)에서 검색한 실제 게시글 URL**만 제공한다.
- 자료가 불충분하면 **무응답(운영방)** + 테스트방 알림(사유 포함)만 남긴다. (FALLBACK 금지)

### 4.2 권장 응답 형태: “최근 3개 링크(제목+URL)”

사용자 경험(운영자 요구):
- “다시보기 링크” → **최근 진행한 무료특강의 다시보기/보너스 안내 글 1개 + 이전 2개(총 3개)** 제공
- “무료특강 링크” → **최근 무료특강 신청 글 3개**를 제목과 함께 제공

실제 구현은 KB 서비스의 신청 게시판 SSOT(무료특강 23 / 정규강의 42)를 기반으로 한다.

참고:
- KB 용어/정책: `docs/kb_glossary.md`
- KB 서비스 로직: `kb/service.py` (`schedule_recent*`, `recent_posts`, `replay_markers`)

### 4.3 모바일 카카오톡 답장 템플릿(예시)

> 아래 예시는 “모바일 카카오톡 UI”에서 **답장(Reply) 박스** 위에 원문 미리보기가 붙고,
> 그 아래에 본문이 표시되는 형태를 기준으로 한다.

#### A) 다시보기 링크(최근 3개)

첫 줄 결론 + 구조화 + 링크는 푸터:

```
😊 최근 무료특강 다시보기(보너스프로그램) 글 3개 링크예요.

1) <제목 1>
2) <제목 2>
3) <제목 3>

---
🔗 관련 링크
<URL 1>
<URL 2>
<URL 3>
```

#### B) 무료특강 신청/공지 링크(최근 3개)

```
😊 최근 무료특강 신청/공지 글 3개 링크예요.

1) <제목 1>
2) <제목 2>
3) <제목 3>

---
🔗 관련 링크
<URL 1>
<URL 2>
<URL 3>
```

#### C) 보너스 프로그램 지급(근거 문장만 짧게 + 링크)

```
😊 보너스 프로그램은 “해당 공지 글” 기준으로 진행돼요.

📌 핵심만 정리하면
- (폼/마감/제출) 관련 문장 1
- (폼/마감/제출) 관련 문장 2

---
🔗 관련 링크
<최신 보너스/다시보기 공지 URL>
```

> 주의: “항상 동일”로 일반화하지 않고, **최신 공지 글의 문장/링크만** 근거로 사용한다(추측 금지).
