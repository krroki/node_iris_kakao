# 강의 운영 v2: CourseOps 웹 콘솔(go.yoorang.kr)

이 문서는 **강의 운영 v2의 “현업 운영 UI”**(ACTIONS 중심)를 웹으로 제공하는 방법과 운영 흐름을 정리한다.

- 관련 ADR: `docs/adr/ADR-0046-courseops-v2-web-console-go-yoorang.md`
- 기존 v2(시트 산출/레거시): `docs/reference/course-roster-v2-membership-audit.md`

---

## 1) 목표

운영진이 “해석” 없이 아래를 바로 처리할 수 있게 한다.

- 해야 할 일(ACTIONS) 확인 → 조치 → **재검증으로 완료 확정**
- 담당자/시간/메모(선택)를 남겨 동시접속에서도 충돌/누락을 줄임

중요: 카카오/Redroid 연동(수집/판정)은 **12.kakao 1대(에이전트)**가 유지한다.  
외부 웹은 카카오에 직접 붙지 않고 “결과 데이터”만 다룬다.

---

## 2) 접속/로그인

- 외부 운영 URL: `https://go.yoorang.kr`
- 인증: **이름 + 공용 비밀번호**
- 자동 로그인: 세션 쿠키(예: 30일)
- 주의: `*.vercel.app` 배포 URL은 Vercel “Deployment Protection(인증)” 설정에 따라 401이 날 수 있다.  
  운영진 접속은 **항상 `go.yoorang.kr`로** 진행한다.

### 새 강의 등록(관리자 전용)

- 새 강의 등록은 **관리자만** 가능하다.
- 설정에서 강의 **수정/삭제(숨김)/복구**도 관리자만 할 수 있다.
- 강의 관리자(강의 등록/수정 + 계정 관리 권한)는 환경 변수 `COURSEOPS_COURSE_MANAGER_NAMES`(콤마 구분 이름 목록)으로 지정한다.
- 운영 초기 부트스트랩을 위해 `COURSEOPS_COURSE_MANAGER_NAMES`가 비어있으면 `glemfkcl`을 기본 강의 관리자로 취급한다.

### 계정 관리(관리자 전용)

- **`/accounts`(계정 관리)** 는 관리자만 접근/노출된다.
  - 사이드바 메뉴도 관리자에게만 보인다.
- 계정을 1명이라도 등록하면(Enabled=true), 이후 로그인은 **등록된 이름만** 허용된다.
  - 쉽게 말해, “명단을 만들기 시작하면” 그 명단에 있는 사람만 들어올 수 있다(관리자는 예외).
  - 단, 관리자는 계정 등록 여부와 무관하게 항상 로그인할 수 있다(잠금 방지).
- 계정별로 다음을 관리한다.
  - 접속 허용(Enabled)
  - 동기화 권한(Can Sync)

### 동기화 실행 권한(옵션)

- 기본값: 로그인한 누구나 동기화(재검증/전체 동기화) 버튼을 사용할 수 있다.
- 제한 모드: “허용된 이름 목록(allowlist)”에 포함된 이름만 동기화 버튼이 활성화된다.
  - 환경 변수: `COURSEOPS_SYNC_ALLOWLIST` (콤마 구분 이름 목록, 비워두면 제한 없음)
  - 참고: `COURSEOPS_SYNC_ALLOWLIST`가 비어있으면, **계정 관리의 Can Sync** 설정을 따른다(관리자는 항상 허용).

## 3) 화면 구성(캡처 기준)

- **작업 대기열**: ACTIONS 카드 목록(필터/정렬 + 처리/검증 상태)
- **대시보드**: 대기 작업/트랙 분포/준수율 등 요약 지표
- **전체 명단**: 통합 테이블(방 참여 현황 + 닉네임/트랙 + 예외 표시)
- **강의 관리**: 새 강의 등록(강의 관리자) + 강의별 카페/톡방/결제 SSOT 연결
- **설정**: 내 화면 설정(대기열 표시 등)
  - 카페는 `clubId`(숫자)가 필요하다. (카페 URL에 `clubid=`가 포함된 주소면 자동 인식되어 입력을 생략할 수 있다.)
  - 결제 SSOT(구글 시트, 읽기)도 강의별로 연결한다.
    - 결제 시트 URL/ID + 탭 이름 + 헤더 행(기본 19) + 컬럼명(기본값 제공)       
    - 시트마다 헤더 행/컬럼명이 다를 수 있다.
      - 예: 쇼츠투벤츠 결제 시트(종합) = 헤더 30행, 구분 컬럼명 `구분 (처음결제 기준)`

## 4) 운영 워크플로우(핵심)

### 4.1) “처리 완료”는 끝이 아니라 “확인 대기”의 시작

1. 작업 대기열에서 카드 1개를 보고 실제 조치를 수행한다.
2. UI에서 `처리 완료`를 누른다.
   - 담당자/시간은 자동 기록된다.
   - 메모는 **선택**(필요한 경우에만 입력).
3. 카드는 “완료”로 즉시 확정되지 않고 **`확인 대기`**로 이동한다.
4. `빠른 재검증` 또는 `전체 동기화`로 실제 반영 여부를 확인한다.

추가 기능(선택):
- 대기열에서 “예외로 두고 싶다”는 항목은 `숨김` 처리할 수 있다.
  - 기본값은 숨김 항목 미표시이며, 필요 시 토글로 다시 볼 수 있다.

### 4.2) 상태 정의(사람이 이해 가능한 단어만)

- `대기`: 시스템이 감지한 해야 할 일(아직 운영진 처리 기록 없음)
- `확인 대기`: 운영진이 “처리 완료”를 눌렀지만, 데이터 반영은 아직 확인되지 않음
- `완료(검증됨)`: 동기화 후 이슈가 사라져 완료가 확인됨
- `미해결(재확인)`: 동기화 후에도 이슈가 남아 있음(조치가 안 됐거나 다른 원인)
- `확인 불가(데이터 미완전)`: 멤버 로딩/수집이 덜 되어 확정 판정이 불가함

---

## 5) 동기화 버튼 2개(필수)

### 5.1) 빠른 재검증(조치 확인용)

목적: 운영진이 방에서 조치한 뒤 “진짜 반영됐는지”를 **빠르게** 확인한다.

- 대상: `확인 대기` 항목들만
- 수집 범위: 항목이 참조하는 **필요한 방만** 갱신(최대 3방)
- 판정: 해당 항목이 사라졌는지/남았는지/확인 불가인지로 상태를 업데이트

예)
- “프리미엄방에 있어야 하는데 없음” 항목이 `확인 대기` 상태
  - 빠른 재검증 → 프리미엄방만 갱신 → 해당 사람이 보이면 `완료(검증됨)`

### 5.2) 전체 동기화(정기 갱신용)

목적: 운영 전체 상태를 최신으로 맞춘다.

- 대상: 코스 전체
- 수집 범위: 오픈채팅(3방) + 카페 + 결제 SSOT(읽기)까지 전체 갱신
- 출력: 작업 대기열/대시보드/전체 명단/감사 로그까지 전체 재계산

## 6) 정확도/엣지케이스(오판 방지 규칙)

### 6.1) 데이터 신뢰도 표시(필수)

톡방 멤버가 “완전히 로딩되지 않은 상태”면 “없다”고 단정할 수 없다.

- 방별 멤버 로딩이 미완료면 판정은 `확인 불가(데이터 미완전)`로 표시한다.
- 운영진이 조치한 케이스라도, 데이터가 불완전하면 `완료`로 확정하지 않는다.

### 6.2) 안정적인 식별(필수)

닉네임은 공백/특수문자/변경 이력 때문에 흔들릴 수 있다.

- “빠른 재검증”은 카드가 참조하는 **대상 식별 키**를 기반으로 체크한다.
- 동일인 매칭은 “현재 닉네임”만이 아니라 “별칭/정규화/결제 SSOT alias”를 포함한 보수적 규칙으로 수행한다.

## 7) 운영/보안 원칙

1. `go.yoorang.kr`은 CourseOps 화면만 노출한다. (기존 운영 UI 외부 노출 금지)
2. 동기화는 **단일 실행(락)** 이어야 한다. (동시 클릭/중복 실행 방지)
3. 장애는 수동 복구가 아니라 **Watchdog 감지 → 자동 조치**가 기본이다.
4. 접속은 네트워크(IP) 제한을 전제로 하지 않는다(어디서든 접속). 제한은 **로그인**으로만 건다.
5. 공용 비밀번호는 주기적으로 교체(로테이션)할 수 있어야 한다.
6. 로그인 실패는 레이트리밋/지연을 걸어 브루트포스를 억제하고, 실패 기록은 감사 로그로 남긴다.

## 8) 도메인(go.yoorang.kr) 연결 개요(운영)

외부 공개는 IP 화이트리스트가 아니라 **HTTPS + 로그인**을 기본으로 한다.

- 권장: Cloudflare Tunnel 사용(포트포워딩 없이 안정적으로 연결)
- `yoorang.kr` 전체를 옮기지 않고도, `go.yoorang.kr`만 별도 존(Zone)으로 만들어 NS 위임 방식으로 운영 가능하다.

> 상세 runbook은 `docs/adr/ADR-0046-courseops-v2-web-console-go-yoorang.md`의 후속 작업에서 별도 문서로 확정한다.

## 9) 코드 위치(구현)

- 웹 콘솔(Vercel): `courseops/console/`
- 로컬 에이전트(12.kakao PC): `courseops/agent/`

### 9.1) 웹 콘솔 필수 환경 변수

- `COURSEOPS_SHARED_PASSWORD` (공용 비밀번호)
- `COURSEOPS_COURSE_MANAGER_NAMES` (강의 관리/계정 관리 권한 이름 목록)
- `COURSEOPS_ADMIN_NAMES` (비상용/레거시: 로그인/동기화 예외 관리자 이름 목록)
- `COURSEOPS_SYNC_ALLOWLIST` (동기화 허용 이름 목록, 옵션)
- `COURSEOPS_SESSION_SECRET` (세션 서명용 시크릿)
- `DATABASE_URL` (Postgres)
- `GOOGLE_SERVICE_ACCOUNT_JSON` (옵션: 결제 SSOT(Google Sheets) 읽기용 서비스 계정 JSON)
- `COURSEOPS_AGENT_TOKEN` (에이전트 인증 토큰)

### 9.2) 로컬 에이전트 실행(예시)

> 운영 환경에서는 Watchdog/스케줄러로 “항상 떠 있도록” 보장한다.

- 필수:
  - `COURSEOPS_CONSOLE_BASE_URL=https://go.yoorang.kr`
  - `COURSEOPS_AGENT_TOKEN=<콘솔과 동일>`
- 선택:
  - `COURSEOPS_AGENT_NAME=<표시 이름>`
  - `COURSEOPS_POLL_SEC=2`
  - `COURSEOPS_REPO_ROOT=C:\dev\12.kakao`

- 참고(로컬 파일로 주입):
  - 시스템 환경 변수 설정이 어렵다면, 로컬(12.kakao PC)에 `node-iris-app/data/courseops_agent_env.json`을 두고 아래 형태로 저장해도 된다.
    - `windows/start_courseops_agent.ps1` / `windows/watchdog.ps1`가 **환경 변수가 비어 있을 때만** 자동으로 읽어 설정한다.
  - 예시(JSON):
    - `{"consoleBaseUrl":"https://go.yoorang.kr","agentToken":"(비공개)","agentName":"courseops-agent"}`

- 실행(권장)
  - `powershell -NoProfile -ExecutionPolicy Bypass -File windows/start_courseops_agent.ps1`

- 자동 복구(Watchdog)
  - `windows/watchdog.ps1`는 `COURSEOPS_CONSOLE_BASE_URL`/`COURSEOPS_AGENT_TOKEN`이 설정돼 있으면 `courseops-agent`를 자동 감지해(heartbeat stale/미실행) 재기동한다.
