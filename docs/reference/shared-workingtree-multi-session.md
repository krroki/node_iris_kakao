# 공유 워킹트리 멀티세션 운영 규칙(4.pint 준용)

이 문서는 “같은 워킹트리(작업 디렉터리)를 여러 세션/프로세스가 동시에 사용”하는 환경에서,
운영 사고(다른 세션 작업 파손/운영 중단)를 막기 위한 **범용 규칙**을 정리한다.

> 이 저장소의 대표 케이스: `C:\dev\12.kakao` (운영 환경 + 여러 세션 공유)

---

## 1) 불변식(절대 규칙)

1. **내 작업 범위 밖 파일은 절대 건드리지 않는다.**
2. 공유 워킹트리에서는 “정리/원복/포맷” 같은 선의의 행동이 가장 위험하다.
3. 운영 중인 상태(프로세스/산출물/캐시)를 흔드는 명령은 금지한다.

---

## 2) Git 금지 목록(치명적)

아래는 “다른 세션 변경” 또는 “운영 상태”까지 같이 날릴 수 있어 금지한다.

- 전체 원복/삭제:
  - `git restore .`
  - `git reset --hard`
  - `git clean -fd`
- 전역 스테이징:
  - `git add -A`
  - `git commit -am ...` (의도치 않은 파일이 포함될 수 있음)
- 워킹트리 흔들기:
  - `git checkout <branch>`, `git switch <branch>`
  - detached HEAD 체크아웃
- pull/merge/rebase:
  - `git pull`, `git merge`, `git rebase` (운영 워킹트리 보호 목적)

> 원격 변경 반영이 필요하면 **별도 clone/worktree**에서 수행하고, 검증된 변경만 옮긴다.

---

## 3) 안전한 작업 방식(권장)

### 3.1) 작업 전 확인

- `git status -sb`로 현재 브랜치/변경 파일을 확인한다.
- 내 작업과 무관한 수정 파일이 보이면 **그 파일은 건드리지 않는다.**

### 3.2) 변경/스테이징/커밋

- 스테이징은 “내가 바꾼 파일만”:
  - `git add <파일경로>`만 사용
  - 가능하면 `git add -p <파일경로>`로 필요한 hunk만 올린다.
- 포맷/린트도 “내가 바꾼 파일만”:
  - repo 전체 포맷/린트는 금지

### 3.3) 테스트/빌드

- 변경한 컴포넌트만 최소 범위로 검증한다.
- 운영 중인 UI/프로세스와 충돌할 수 있는 빌드/삭제는 주의한다.
  - 예: Next.js 운영 UI 실행 중 `web` 빌드/산출물 삭제 금지(필요 시 `start_web.ps1` 절차 사용)

---

## 4) 실수 복구(즉시)

### 4.1) 브랜치가 `main`이 아니게 된 경우

파일을 건드리지 말고 즉시 복구한다.

- 복구:
  - `git symbolic-ref HEAD refs/heads/main`
- 확인:
  - `git status -sb`가 `## main`인지 확인

### 4.2) 워킹트리가 꼬여 “무조건 원복”이 떠오를 때

공유 워킹트리에서는 `reset --hard`/`clean -fd`가 다른 세션을 파괴할 수 있다.

- 금지: 전체 원복/삭제
- 대신:
  - 내 변경 파일만 선별적으로 되돌리거나(담당자와 합의),
  - 아예 별도 clone/worktree에서 작업을 이어간다.

---

## 5) 운영 철학(중요)

공유 워킹트리는 “개발 디렉터리”가 아니라 “운영 환경”일 수 있다.

- 운영 중인 상태를 흔들지 않기 위해, **부분 재기동/부분 검증**을 우선한다.
- 자동 복구가 가능한 문제는 Watchdog가 해결하도록 설계한다(수동 조치 최소화).
